# Operator guide

1. Follow README setup, start the local app, and open the bundled study. Keep the SYNTHETIC label visible when showing it to others.
2. Click **Generate measurement plans**. Select a baseline card to see its sites. Reduce budget from 350 to 120 and regenerate; only affordable deployments should remain.
3. Select Footbridge on the map or Sites dropdown. Uncheck permission and rerun. That site must not be recommended. Never treat a site suggestion as permission to enter or approach a hazardous source.
4. Save investigation. Open the investigation dropdown to reopen it or create a new study. Save before switching: unsaved changes are replaced.
5. For your own data, create a **new** investigation, enter area bounds, concern and objective. Choose **Import data**, a measurement CSV, and map required columns. Required fields: `sensor_id,timestamp,latitude,longitude,pm25_ug_m3`. Use µg/m³, decimal geographic coordinates, and timestamp offsets. Choose an IANA timezone such as `America/New_York` if timestamps lack offsets; ambiguous daylight-saving times need explicit offsets.
6. Inspect **Data quality**. Invalid rows remain in the raw import but are absent from the normalized table. Negative/duplicate/extreme-review rows remain visible but are excluded from fitting. Correct errors in a new source file rather than overwriting the original record. Add instrument/calibration provenance notes; no correction is applied automatically.
7. Import weather separately if appropriate: `timestamp,latitude,longitude,wind_speed_m_s,wind_from_deg`, direction **from north**, m/s. A distant station is an approximation, not local truth. Without representative weather, choose **Spatial coverage**.
8. Mark sites using **Add to map**, then click a position. Enter cost, permission, power/battery, safe access and availability. Enter candidate source locations only as hypothetical scenarios. At most 25 source locations and 100 sites.
9. Experimental source planning additionally requires steady open/neutral conditions and two usable distinct sensors in a ≤1 hour observed period, with supported local wind. For longer campaigns, use Scenarios → Campaign periods and physical metadata to declare2–6 separately steady periods (each≤1hour, nonoverlapping, span≤14days), with an explicit fixed-source/constant-release assertion. Do not use this when release location or strength changes; split into separate studies instead. The timeline filter changes exploration only. Future scheduling is unsupported. Refusals are not permission to invent weather.
10. Import follow-up readings into the same study to append them. Previous analysis is invalidated; past comparisons remain in history. Recompute and inspect unresolved questions. Review the cross-period spatial-contrast checks and declared met uncertainty. A missing warning cannot establish that the constant-release or weather assumptions are correct. Longer or incompatible campaigns need separate studies or spatial coverage.
11. Record resident observations separately at approximate locations. Avoid names and private details. A reported odor does not identify chemical composition or responsibility.
12. **Export evidence** saves first. HTML is self-contained: open it locally and use browser Print → Save as PDF. Review limitations, provenance, free text and privacy. JSON is a **private archive** with exact coordinates/raw files, and can be restored through the investigation dropdown. CSV is normalized data, not a substitute for raw originals.

Use `examples/synthetic-measurements.csv`, `synthetic-weather.csv`, and `malformed-measurements.csv` only in disposable synthetic demonstrations. `synthetic-investigation.json` can restore the entire example. **These files are not real measurements**; importing a CSV into an unlabeled new study does not make it real. The supplied files carry `origin=synthetic`; this automatically labels the investigation and survives report/CSV/JSON export. Preserve that column and use the bundled investigation for public demonstrations.

Troubleshooting: no readings → inspect headers, timestamp errors and units; no plan → inspect budget and all site eligibility checks; missing weather → use geometry or obtain appropriate observations; tiles unavailable → offline grid; large CSV → split to ≤2 MB/10,000 rows and note investigation aggregate bounds. API has an 8 MB request limit; a private archive with many raw imports may require splitting the investigation before adding more files. Nothing is sent automatically.

Current research model0.4: **Scenarios → Open synthetic campaign example** preserves a dirty current study by saving it before loading the example. Complete or remove invalid period entries before analysis. **Analyze current study** is available directly in Scenarios. The optional concentration-prediction objective is separate from source identification. All recommendations remain research-only; read [the current capability decision](../RESEARCH_RESULTS.md) before any organizational use. The offline map uses compact site IDs to keep dense sites readable; selecting one reveals its full name/constraints.
